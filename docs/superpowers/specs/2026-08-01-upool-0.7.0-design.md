# U-Pool 0.7.0 — design

Status: implemented 2026-08-01. Records the decisions the code now encodes;
where a claim is named here, widening it is a data-loss change.

## Why

Three gaps, all measured on the author's machine rather than assumed:

1. **Two installed CLIs are unmanaged.** `%LOCALAPPDATA%\hermes\config.yaml` is a
   live 754-line document with four real providers in it. `~/.config/opencode/`
   exists, and `opencode.cmd` sits in `%APPDATA%\npm` beside `claude.cmd` and
   `codex.cmd`. `cc-switch` treats both as first-class app targets; U-Pool did
   not know they existed.

2. **Transcripts accumulate with no way to clear them.** `~/.claude/projects` was
   936 files / 230 MB; `~/.codex/sessions` plus `archived_sessions` 53 files /
   29 MB. Both sit in the same directory as the credentials, which is precisely
   why a delete has to be a fixed list rather than a sweep.

3. **No way to see which CLI version is installed.** The header showed U-Pool's
   own version only, which is the least interesting of the three.

## Scope

| # | Change |
|---|--------|
| 1 | Hermes as a fourth tab, with a real adapter |
| 2 | OpenCode as a fifth tab, with a real adapter |
| 3 | `upool.yamlio` — parse to read, splice to write |
| 4 | `upool.sessions` — delete all transcripts, per app, from a fixed table |
| 5 | `upool.clis` — probe the installed Claude Code and Codex versions |
| 6 | Header gains the two version readouts and a refresh button |
| 7 | `paths.sandboxed()` — env-var overrides ignored under a fake home |

| 9 | `Store._seed_new_apps` — an upgraded config gets the new tabs seeded |
| 10 | Version 0.6.0 → 0.7.0 |

## 1. Hermes — `src/upool/adapters/hermes.py`

Config resolution, in order: `HERMES_HOME`, then `%LOCALAPPDATA%\hermes` on
Windows, then `~/.hermes`. File is `config.yaml`.

Written shape, matching the live install rather than cc-switch's `custom_providers`
list — the real file keeps providers in the `providers:` **mapping** with `api`
and `transport` keys, and `custom_providers` is empty:

```yaml
model:
  provider: <slug>
  default: <model>
providers:
  <slug>:
    name: <name>
    api: <base_url>
    api_key: <key>
    transport: anthropic_messages | chat_completions | codex_responses | bedrock_converse
    default_model: <model>
    models:
      <model>: {name: <model>}
```

### The claim, and why it is narrower than Codex's

The Codex adapter deletes every `[model_providers.*]` table but the active one,
because Codex was reading two at once and the pile of dead tables *was* the bug.
**Hermes must not do that.** Hermes reads exactly the entry `model.provider`
names; the rest of the mapping is inert, and on the machine this was written for
it holds four entries the user added by hand.

So the claim is:

- `providers.<slug>` for the slug being written, plus any slug U-Pool wrote before
  and is now replacing — recorded in `upool.claims` under `"hermes_providers"`
- `model.provider` and `model.default`

Everything else — other entries in `providers:`, other keys in `model:` such as
`context_length`, and all ~35 unrelated top-level sections — is read, kept and
written back byte for byte.

`env_namespace = ""`. Hermes reads its key out of `config.yaml`, so nothing goes
to `HKCU\Environment`.

## 2. OpenCode — `src/upool/adapters/opencode.py`

`~/.config/opencode/opencode.json` on every platform including Windows, or
`OPENCODE_CONFIG` where set.

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "<slug>/<model>",
  "provider": {
    "<slug>": {
      "npm": "@ai-sdk/anthropic",
      "name": "<name>",
      "options": {"baseURL": "<base_url>", "apiKey": "<key>"},
      "models": {"<model>": {"name": "<model>"}}
    }
  }
}
```

Claim: `$schema`, `provider.<slug>` (current and previously-claimed, namespace
`"opencode_providers"`), and the top-level `model`.

**`model` is a widened claim relative to cc-switch**, which treats it as
user-owned and writes only the provider block. Without it a switch defines a
provider without selecting one, which is not a switch. It is the only claim here
wider than the reference implementation, and it is the reason `model` is a
required field for this app in `validate()`.

`theme`, `mcp`, `plugin`, `agent`, `keybinds` and unclaimed `provider.*` entries
survive. `options` is merged rather than replaced, so headers and SDK flags the
form never asks for outlive a key rotation. `env_namespace = ""`.

## 3. `src/upool/yamlio.py` (new)

- `read(path)` — `yaml.safe_load`; raises `UPoolError` on a parse failure so a
  broken file refuses the write, matching `CodexAdapter._read_config`.
- `sections(text)` — half-open line range per top-level key. A top-level key is
  `^[A-Za-z_][\w.-]*:` at column zero. Blank lines and column-zero comments
  trailing a section are trimmed out of its range, so they read as separators for
  the next one and survive a replacement.
- `splice(text, changes)` — re-serialises only the named sections and swaps them
  into their line ranges, highest line first. `None` removes; an absent key is
  appended.

Full round-trip was rejected: it preserves every value and still rewrites every
line, and a 700-line diff to change six of them is unreviewable.

Measured against the real config: **754 lines in, 13 changed.**

## 4. `src/upool/sessions.py` (new)

`TARGETS` is a literal table and is the entire scope of the feature.

| App | Deleted |
|-----|---------|
| `claude` | `~/.claude/projects` (contents), `~/.claude/sessions` (contents), `~/.claude/history.jsonl` |
| `codex` | `~/.codex/sessions`, `~/.codex/archived_sessions` (contents), `~/.codex/history.jsonl`, `~/.codex/session_index.jsonl` |

Not touched, and the reason the table is a table: `settings.json`,
`.credentials.json`, `auth.json`, `config.toml`, `plugins`, `skills`,
`file-history`, `shell-snapshots`, `.tmp`. A glob over either directory takes a
login with it.

- `summary(app)` → per-entry `{path, exists, files, bytes}` plus totals.
- `purge(app)` → `{deleted, freed, errors}`. Per-item failure is an entry in
  `errors`, not an abort: a transcript held open by a running CLI is ordinary,
  and leaving 900 other files behind because of it makes the button unreliable.
- Directories are emptied, not removed — the CLI expects to find them.
- `_guard` refuses any target that is not strictly under `paths.home()`. Nothing
  a user types reaches these paths, so it fires only on a resolution bug, which
  is exactly the failure that would make a delete unbounded.
- **No backup.** A second copy of 230 MB somewhere the user did not ask for is
  not a safety net. The UI says so before it asks.

Apps absent from `TARGETS` raise rather than defaulting to nothing, so a future
tab cannot quietly acquire a delete button that does nothing — or worse, guesses.

## 5. `src/upool/clis.py` (new)

Probes `claude` and `codex` only.

Resolution is `shutil.which` first, then a sweep of `%APPDATA%\npm`,
`%LOCALAPPDATA%\npm`, `%ProgramFiles%\nodejs`, `~/.bun/bin`, `~/.local/bin`.
The fallback is load-bearing: U-Pool runs windowed, launched from Explorer or the
sign-in entry, and inherits the PATH as it stood at logon — on this machine
`claude.cmd` is in `%APPDATA%\npm`, which is on the interactive PATH and not the
inherited one.

`subprocess.run([exe, "--version"], timeout=15, creationflags=CREATE_NO_WINDOW)`,
version read with `\d+\.\d+\.\d+(?:[-+][\w.]+)?` from stdout then stderr.

Found-but-silent is reported separately from not-found: a broken shim and an
absent install need different fixes, and collapsing them sends the user to
reinstall something that is already there.

`snapshot()` / `refresh_async()` mirror the updater: `bootstrap` returns the cache
immediately and starts a thread, the UI polls while `busy`. Blocking first paint
on two Node launches was not acceptable.

## 6. `paths.sandboxed()`

Hermes resolves through `%LOCALAPPDATA%` and `HERMES_HOME`; OpenCode through
`OPENCODE_CONFIG` and `XDG_CONFIG_HOME`. Redirecting `UPOOL_FAKE_HOME` alone
therefore left two write targets aimed at the developer's live install — the
exact hazard `CLAUDE.md` exists to prevent.

Rather than have every caller clear four more variables, those overrides are
ignored whenever `UPOOL_FAKE_HOME` is set. `tests/conftest.py::_assert_sandboxed`
and `scripts/sandbox.py` both assert the four config paths resolve inside the
sandbox before anything is allowed to run.

The suite also stubs `clis.resolve` to find nothing. `Api.bootstrap` starts a
probe, and unstubbed it ran the developer's own `claude.cmd` twice per bootstrap
— which turned a 35-second suite into one that did not finish, and was not
hermetic even when it was fast.

## 7. Seeding an upgraded config

`Store._bootstrap` only runs when there is no `config.json` at all, so an install
upgrading from 0.6.0 got Hermes and OpenCode tabs with **no rows** — caught by
launching the app, not by the suite, which always starts from an empty home.

Empty is not a neutral state here: the official entry is the only way to hand
control back to the vendor, and it cannot be created from the provider form. So
`_normalise` now calls `_seed_new_apps`, which fills any slot that has no
providers with the official seed plus whatever `import_live` finds. It only ever
adds, and only to an empty slot — an app the user deliberately emptied keeps what
they left.

## 8. UI

- `AppId` gains `hermes` and `opencode`. Six exhaustive `Record<AppId, …>` maps
  had to grow an entry — `TAB_MARK`, `TAB_TINT`, `URL_HINT`, `BYPASS_HINT`, and
  four in `mock.ts`. `presetsFor` became an exhaustive `CATALOGUES` lookup rather
  than a chain of tests, so the next app id fails to compile instead of silently
  inheriting the Codex templates.
- Tab marks are the real logos: `ui/public/brands/opencode.svg` was already in
  the repo, and the Hermes mark is the Nous Research illustration from
  hermes-ai.net. It is an opaque black-and-white drawing, so it renders through a
  plain `<img>` (`ImageMark`) rather than `MaskMark`, which drives its shape from
  alpha and would show a solid square. The hand-drawn stand-ins written before
  the real marks were sourced — a winged helmet and a terminal prompt — are
  deleted rather than kept as fallbacks: a wrong logo is worse than none.
- `Provider` gains `transport` (Hermes) and `npm` (OpenCode), rendered as Selects
  in the same slot the auth-style and wire-API fields occupy. Neither app has a
  permission model U-Pool can drive, so the toggles block is absent for them.
- Header: two mono version pills beside the wordmark, a `RefreshIcon` button that
  spins while probing. Five tabs plus the readouts do not fit 760px, so the
  toolbar is `max-w-[1040px]` and `MIN_SIZE` went from 940 to 1040 — a header
  that reflows is worse than a window that will not narrow past it.
- Settings: an **Installed CLIs** section with resolved paths, and a **Sessions**
  section with one red `Button variant="danger"` per app carrying live counts.
  Deleting is two clicks, and the confirm modal names every path.

- `python scripts/sandbox.py scripts/probe_0_7_0.py` — copies the machine's real

  top-level section comes back byte-identical and every hand-written provider
  survives. 13 of 754 lines changed.
- `npm run build` in `ui/` — TypeScript clean.
